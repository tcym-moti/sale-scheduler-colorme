# 審査担当者向け操作手順

## 前提

1. 審査用のカラーミーショップへログインできる状態にする。
2. Sale Schedulerの独立OAuth Appをインストールする。
3. `read_products`と`write_products`の認可を許可する。
4. バリエーションのないテスト商品を1件以上用意する。

## 通常フロー

1. アプリ設定ページを開く。
2. 商品名または商品IDで検索する。
3. バリエーションのない商品を1件選択する。
4. 固定セール価格、または割引率を指定する。
5. 開始日時と終了日時を指定する。
6. Previewで商品名、現在価格、セール価格、値引額、対象商品数、開始・終了の概算処理時間を確認する。
7. Previewに「API制限により、指定日時から商品ごとに順次反映される」旨が表示されることを確認する。
8. 予約を確定する。
9. 指定日時を過ぎた後、外部ショップ管理画面または履歴でセール価格を確認する。
10. 終了日時を過ぎた後、元価格へ復元され、予約が完了になることを確認する。

指定日時は全商品が同じ秒に変更される時刻ではありません。複数商品では、開始日時から順番に反映されます。

## Conflictフロー

1. 1件の商品で予約を作成し、開始処理を完了させる。
2. セール中にショップ管理画面から、その商品の価格を別の値へ変更する。
3. 終了処理を待つ。
4. アプリが元価格へ上書きせず、商品単位で`CONFLICT`として停止することを確認する。
5. 履歴で元価格、セール価格、現在価格、理由を確認する。

## 安全性の確認ポイント

- 開始時は開始直前の価格を`effective_original_price`として保存する。
- 終了前GETがセール価格以外ならPUTを実行しない。
- PUT後のGETが一時的に古い値でも、有限回のverification retryを行う。
- verificationが確定しない場合は`VERIFY_UNKNOWN`または`POST_WRITE_DIVERGENCE`とし、追加PUTを実行しない。
- ブラウザを閉じてもWorkerが予約を継続する。

## MVPの対象外

バリエーション価格、`option_price`、会員価格、定価、CSV、画像、外部EC連携は対象外です。
